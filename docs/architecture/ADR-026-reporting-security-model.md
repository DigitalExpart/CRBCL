# ADR-026: Reporting & Analytics Security Model

## Status
Accepted

## Context
CRBCL requires an organization-wide reporting, analytics, and quality assurance framework. However, child welfare and family wellness data includes extremely sensitive medical records, criminal background checks, confidential intake reporter identities, financial ledger entries, and conflict-of-interest case restrictions. Standard reporting tools often create data leaks by allowing users to bypass field-level, row-level, or team-level authorization boundaries when generating reports or exporting spreadsheets.

## Decision
We enforce a **Zero-Bypass Reporting Security Architecture**. Reporting endpoints and the metadata query generator must strictly derive data through the existing FastAPI authorization layer, applying the exact same scope rules, field-level redactions, and case restriction filters as primary domain services.

### Key Rules:
1. **No Universal Raw SQL**: Reports cannot accept arbitrary SQL fragments or un-validated table/column names from users. All queries are generated server-side using an approved metadata catalogue.
2. **Row-Level & Scope Enforcement**: Every report query automatically joins case assignment, team assignment, and case restriction tables (`case_restrictions`). If a case is restricted for a worker due to a conflict of interest, it is automatically omitted from report datasets generated by that worker.
3. **Field-Level Sensitivity Enforcement**:
   - `client.medical.read`: Required to include medical diagnosis, health number, or prescription details in reports or Child Passports.
   - `intake.reporter.read`: Required to view referral reporter names or contact info in Intake Reports.
   - `finance.request.read` / `finance.budget.read`: Required to include financial request amounts or budget allocations.
   - `background_check.read`: Required to view detailed background check findings in Placement Home reports.
4. **Export Audit Trail**: Every export (XLSX, PDF, CSV) logs a `REPORT_EXPORTED` audit event containing user ID, dataset key, row count, and timestamp.
5. **No Public Export URLs**: Temporary export files generated asynchronously are stored in private storage with short-lived, authenticated download tokens.

## Consequences
- Reports and exports are 100% compliant with CRBCL confidentiality policies.
- Users cannot craft malicious queries to extract restricted child or financial data.
- Medical and reporter identity columns are automatically omitted from report queries if the requesting user lacks specific permission.
